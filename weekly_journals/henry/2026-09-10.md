# Week 4 Weekly Journal - Henry Smith

## What I Did

- Reviewed the decoder and integrity-validation behavior after the Week 3 code was merged into the team branch.
- Added local regression coverage for empty cover/payload combinations, punctuation, line breaks, malformed byte blocks, unrelated zero-width characters, UTF-8 file input/output, and 100 generated encode/decode round trips.
- Added a safe repeated-embedding check so the program reports a clear error instead of treating two adjacent hidden frames as one ambiguous payload.
- Added `count_codec_characters()` to report counts for `U+200B`, `U+200C`, and `U+200D`. Tristan can use these values to calculate character-survival rates from platform test samples without relying on visual inspection of invisible characters.
- Updated the codec documentation and README with the validation behavior and measurement helper.

## What I Learned

- A valid local round trip is not enough: file encoding, line breaks, malformed byte blocks, and repeated embedding must be handled or rejected consistently.
- Clear detected failures are preferable to returning unverified data after a platform changes hidden characters.
- Counting each zero-width character by code point makes platform-testing measurements reproducible even when a user interface cannot display invisible symbols.

## Problems Encountered

- The current baseline format cannot safely distinguish two adjacent frames because it does not have a separate frame-boundary marker. The encoder now rejects repeated embedding rather than allowing an ambiguous result.
- Platform testing is still required to determine how specific applications alter the three selected zero-width characters; those measurements are assigned to Tristan.
