## What I Did

- Worked on the first local zero-width Unicode encoder and decoder for Team A's Project 5.
- Used the agreed mapping: `U+200B` for binary `0`, `U+200C` for binary `1`, and `U+200D` as the byte separator.
- Documented a draft frame that contains a format marker, UTF-8 payload length, payload, and CRC-32 checksum so damaged data is rejected rather than returned as if it were correct.
- Added reusable test vectors and automated local tests for the four initial Week 3 messages, an empty message, accented text, multilingual text, emoji, visible-cover preservation, deterministic output, and malformed input.

## What I Learned

- Invisible Unicode symbols can represent binary data without changing the visible cover text.
- A decoder needs framing and validation because missing or altered invisible characters can otherwise produce misleading output.
- UTF-8 tests are important because the project must support more than ASCII text.
- Automated tests make it possible to check local round trips consistently before the team begins platform testing.

## Problems Encountered

- Zero-width characters are hard to inspect visually, so test code must compare the recovered secret exactly and separately verify that the visible cover text is unchanged.
- This baseline codec assumes the cover text does not already contain the project's three zero-width characters. Platform behavior and error correction remain later-scope work.
